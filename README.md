# DDwifi4
# DDwifi4 — 災害時の利用を想定したオフラインコミュニケーションアプリ

大学在学中に、学内のチームアプリ開発コンテストで制作したAndroidアプリです。

災害時など、インターネット接続を利用できない状況での情報共有を想定し、Wi-Fi Directによる端末間通信と、端末内にデータを保存する掲示板機能を実装しました。

近くの端末同士を接続して、投稿内容・掲載期限・位置情報を交換する仕組みです。

## 開発背景・目的

災害時には、通信環境の悪化によって普段の連絡手段を利用しにくくなることが考えられます。

そこで、インターネット上のサーバーを経由せず、近くにある端末同士で情報を共有するアプリをチームで制作しました。周辺の状況や必要な情報を投稿し、接続した端末間で持ち寄れる仕組みを目指しました。

## 主な機能

| 機能 | 内容 |
|---|---|
| 近くの端末の探索 | Wi-Fi Directで周辺端末を探索し、一覧に表示 |
| 端末間の接続 | 一覧から相手端末を選択して接続 |
| 投稿データの交換 | 保存済みの投稿をJSON形式で送受信し、受信した投稿を端末内に保存 |
| 掲示板 | 投稿の作成、一覧表示、削除 |
| 掲載期限 | 投稿ごとに期限を設定。未指定の場合は24時間後 |
| 期限切れ投稿の除外 | 期限が過ぎた投稿を取得・表示対象から除外 |
| 位置情報 | 投稿に緯度・経度を付与 |
| 距離・方角の表示 | 自分の位置から投稿場所までの距離と8方位を表示 |
| 投稿場所の詳細 | 位置表示をタップすると緯度・経度を表示 |
| 距離による表示範囲 | 指定した距離内の投稿を表示する処理 |
| キーワードの強調表示 | 入力した文字列と一致する部分を赤色で表示 |
| 一覧の更新 | 更新ボタン、または下に引く操作で保存済み投稿を再読み込み |

距離の設定は、掲示板の表示対象を絞るためのものです。Wi-Fi Directの通信距離を変更する機能ではありません。

キーワード入力は一致部分を強調する機能であり、一致する投稿だけに一覧を絞る機能ではありません。

## 通信の仕組み

1. Wi-Fi Directで近くの端末を探索します。
2. 接続する端末を一覧から選択します。
3. 接続後、グループオーナー側がサーバー、もう一方がクライアントとして動作します。
4. TCPソケットを使い、ポート番号`3184`で投稿データを交換します。
5. 受信した投稿を、それぞれの端末のSQLiteデータベースに追加します。
6. 双方の送受信完了を確認すると、接続を終了する処理があります。

送信するデータは、投稿本文、掲載期限、緯度、経度です。

現在の実装は、接続時に保存済みの投稿を交換する方式です。新しい投稿を作成するたびに相手へ即時配信する、常時接続型のチャットではありません。

Wi-Fi Directによる端末間通信には、インターネット接続や共通のWi-Fiルーターは不要です。ただし、端末のWi-Fi機能は有効にする必要があります。

## 主なコードの構成

Javaのコードは、`app/src/main/java/com/example/ddwifi4/`にあります。

| ファイル | 役割 |
|---|---|
| `MainActivity.java` | メイン画面、周辺端末の探索・接続、ソケット通信、投稿データの送受信 |
| `WiFiDirectBroadcastReceiver.java` | Wi-Fi Directの状態変更、端末一覧の変化、接続状態の通知を処理 |
| `Database.java` | 掲示板画面、投稿作成、位置情報取得、距離による表示範囲、一覧更新 |
| `DatabaseHelper.java` | SQLiteの作成、投稿の保存・取得・削除、JSONへの変換 |
| `Post.java` | 投稿データを保持するクラス |
| `PostAdapter.java` | 投稿一覧の表示、キーワード強調、距離・方角表示、削除確認 |
| `LocationSensor.java` | 位置情報の更新開始・停止、LiveDataによる通知 |
| `LocationCalc.java` | 距離・方角を計算する補助クラス |

主な画面レイアウトは、`app/src/main/res/layout/`の`activity_main.xml`と`activity_database.xml`です。

`LocationCalc.java`には計算処理がありますが、現在の掲示板表示では主にAndroidの`Location`クラスによる距離・方角計算を使用しています。

## データの保存

投稿は、端末内のSQLiteデータベース`bulletin_board.db`に保存します。

保存する項目は以下のとおりです。

- 投稿ID
- 投稿本文
- 投稿日時
- 掲載期限
- 緯度
- 経度

期限切れの投稿は取得対象から除外します。期限が切れた時点でデータベースから自動削除する仕組みではありません。

端末間の交換では、元の投稿IDと投稿日時を引き継がず、受信側で新しい投稿として登録します。

## 実行方法

### 必要な環境

- Android Studio
- ビルド用JDK 17
- Android SDK Platform 34
- Wi-Fi Directに対応したAndroid実機2台
- 位置情報機能とGoogle Play services Locationが利用できる端末

Javaのソースコードの互換性設定はJava 8ですが、Android Gradle Plugin 8.6.0を動かすビルド環境にはJDK 17が必要です。

### プロジェクトを開く手順

1. このリポジトリの「Code」から「Download ZIP」を選択します。
2. ダウンロードしたZIPを展開します。
3. Android Studioで「Open」を選択します。
4. `settings.gradle.kts`があるフォルダを開きます。
5. Gradleの同期が完了するまで待ちます。
6. 必要なSDKのインストール案内が表示された場合は、案内に従います。
7. Android実機を接続し、実行対象を`app`にして起動します。
8. 通信を試す場合は、もう1台にも同じアプリをインストールします。

初回のビルドでは、Gradleや依存ライブラリなどのダウンロードにインターネット接続が必要です。アプリの端末間通信がオフラインで行えることとは別の条件です。

`local.properties`はPCごとのAndroid SDKの場所を指定するファイルのため、リポジトリには含めていません。Android Studioで開く際に、利用するPCのSDK設定を行ってください。

## 基本的な使い方

1. 両方の端末でWi-Fiと位置情報を有効にします。
2. アプリを起動し、位置情報へのアクセスを許可します。
3. 必要に応じて「GPS_ON」で位置情報の更新を開始します。
4. 「掲示板を開く」から掲示板画面へ移動します。
5. 「＋」ボタンから投稿内容を入力し、必要に応じて掲載期限を設定します。
6. メイン画面に戻り、「探索開始」を押します。
7. 一覧から相手端末を選び、端末に接続確認が表示された場合は許可します。
8. 投稿データの交換後、掲示板を開いて更新し、受信した投稿を確認します。

投稿作成と掲示板表示では位置情報を使用します。位置情報を取得できない場合、投稿を保存できないことがあります。

## 設計・実装上のポイント

### サーバーを経由しない情報交換

Wi-Fi DirectとTCPソケットを組み合わせ、近くの端末同士で投稿データを交換する構成にしました。

### 投稿のローカル保存

受信した内容をSQLiteに保存し、端末間の接続を終了した後も掲示板から参照できる構成です。

### 掲載期限と位置情報の活用

投稿に期限と位置情報を持たせることで、情報の新しさや投稿場所との位置関係を確認できるようにしています。

### 処理の役割分担

画面操作、データ保存、一覧表示、位置情報取得を複数のクラスに分けています。通信処理は別スレッドで行い、必要な画面更新をUIスレッドで実行する構成です。

## 現在の課題・改善案

公開コードには、次の改善余地があります。

- **Android 13以降の権限対応**  
  `NEARBY_WIFI_DEVICES`はManifestに宣言していますが、実行時の許可要求が不足しています。対象OSでの端末探索・接続には対応が必要です。

- **距離設定の文字列処理**  
  `parseDistance()`が`km`より先に`m`を判定しているため、`1km`などの選択で数値変換エラーが起きる可能性があります。

- **位置情報取得前の画面操作**  
  一覧表示用のAdapterは位置情報取得後に初期化します。取得前の更新操作などで初期化前のAdapterを参照しないよう、制御を改善する必要があります。

- **通信データの分割・結合への対応**  
  受信は1024バイト単位で読み取った内容を、そのまま1件のメッセージとして扱っています。TCPの受信区切りは送信区切りと一致するとは限らないため、データ長や区切りを使った受信処理が必要です。

- **重複投稿の防止**  
  受信した投稿を新規登録するため、同じ端末と再び交換すると投稿が重複する可能性があります。端末間で共有できる投稿IDなどの導入が改善案です。

- **認証・データ保護**  
  接続時に固定コードを照合する処理がありますが、利用者ごとの本人確認や、アプリ独自の暗号化は実装していません。

- **接続処理の安定化**  
  接続開始、データ送信、切断、再接続の状態管理と例外処理を改善する余地があります。

- **テストの拡充**  
  リポジトリ内のテストは、加算結果とアプリのパッケージ名を確認するサンプルです。投稿管理や端末間通信の動作を検証するテストの追加が必要です。

## チーム開発と自身の担当範囲

本アプリは、大学在学中の学内チームアプリ開発コンテストで制作した作品です。

私は、**Wi-Fi Directを用いた端末間通信の部分**を担当しました。災害時などインターネット接続を利用できない状況でも、近くの端末同士で情報を共有できるようにする、アプリの通信機能に取り組みました。
